# Broadcast Presentation Overhaul — Pass 2 (M1–M8)

## Context
A first broadcast programme (B0–B8, D-069/D-070, "PROGRAM COMPLETE 2026-11-23") already shipped a post-game replay viewer: event timeline, graphics strip, camera director/rig, 2D + reduced 3D viewer, reconstruction, audio cues, caption commentary, highlights, lineup card. The new brief turns this "developer replay tool" into a TV-style broadcast. This plan EXTENDS those classes; nothing is rebuilt. Decisions taken with the founder: (1) "close-up" = medium shot at the 28 ft 3D minimum plus a 2D spotlight graphic (D-070 unchanged); (2) shot clock/stoppages are presentation-only, labelled "reconstructed", no sim or save change, no fake timeouts; (3) commit + push each milestone.

## Audit summary (verified)
- Reuse as-is: `FcBroadcastTimeline` (running state, `seconds_at`, `index_at_seconds`, `replay_window`), `FcBroadcastGraphics.items_at/lineup_card`, `FcBroadcastOverlay`, `FcCameraDirector.shot_for` (pure), `FcCameraRig` (auto/hybrid/manual, easing), `FcReconstructor` (deterministic keyframes), `FcHighlights`, `FcCommentary`, `FcBroadcastAudio`, `FcAudio`/`FcAudioSynth`, `FcCourtScene` (MultiMesh crowd 6000), `FcScoreBug`, `FcReplayScreen` (592 lines, one screen for all three modes).
- Modify: `replay_screen.gd` (too large; split into mode shells), `camera_director.gd` (new presets, transition types), `broadcast3d_rules.gd` (camera pose per preset), `court_scene.gd` (benches, LED content, lighting, crowd), `score_bug.gd`, `preferences.gd` (HUD option; pref keys need defaults, no data-version bump needed unless shape of saved profile changes — check `FcVersion`).
- Missing: lower-third/spotlight graphics, collapsible feed, contextual camera panel, HUD visibility, shot clock, importance model, bookmarks, ambience loops/ducking, announcer/commentary event queue, pregame/halftime/postgame production, benches, LED content, crowd variation.
- Hard limits: no positions/passes/timeouts in event log (rows `[type, clock_tenths, side, a, b, x]`); reconstruction is plausible, not truth (19.5% of steps exceed game clock) — replay must stay labelled "reconstructed" and never claim exact motion; no 3D on mobile (D-030); perf gates in `docs/validation/PERFORMANCE_THRESHOLDS.md` (p95 16.6 ms, p99 33.3 ms); music bus stays empty (no unlicensed audio, D4); screenshots need a real window (`tools/screenshot.ps1`), not headless.

## Milestones (each: scope → implement → unit/live tests → screenshots → regression run → docs → commit+push; one Godot process at a time)
Order is by dependency: pure data first, UI shell second, then 3D/audio.

**M1 — Presentation modes + HUD shell (Phase 2 core).** Split `FcReplayScreen` into three explicit modes (Broadcast / Replay / Analysis) via a small pure `FcPresentationMode` + HUD-visibility state (`Full`, `Minimal`, `Hidden`) stored in Preferences. Full-screen stage layout with 3D court dominant; collapsible feed/side panels; contextual camera panel (shows manual controls only in manual/hybrid, collapsible); layouts verified at 1920x1080, 2560x1440, 3440x1440. Accept: mode switch never changes replay index; HUD toggle hides all overlays; existing `test_live_replay`, `test_live_camera` still pass.

**M2 — Broadcast graphics (Phase 2 graphics).** New scoreboard (team crest via `src/ui/team/`, score, clock, shot clock, quarter, team fouls/bonus, possession) extending `FcScoreBug`; animated lower thirds + player spotlight + scoring updates + stat overlays built from `FcBroadcastGraphics`/`FcBroadcastTimeline.player_line` only (every text must equal play-by-play/box score — add test). Pure `FcShotClockModel`: derives possession start from reconstructed keyframes, labelled reconstructed, hidden when unknown. Accept: unit tests for text equality; screenshots at 3 resolutions.

**M3 — Camera director v2 (Phase 3).** Extend `FcCameraDirector` presets: main broadcast, baseline, tactical overhead, close-up (28 ft medium, per D-070), replay, free throw (exists), celebration (after made baskets/runs/final), stoppage (foul, sub, period break). Add per-shot angle/height, transition types (cut, ease, whip/crossfade) and a configurable transition-speed/“director style” preference. Possession side drives baseline/main choice. `broadcast3d_rules.camera_pose` maps presets to 3D poses; manual controls and Flat/2D views preserved. Accept: pure tests (event→preset table, hold/priority, determinism); live camera test unchanged.

**M4 — Replay v2 (Phase 4).** Unified `FcImportanceModel` (extends `FcHighlights` weights + director priority, one source of truth); timeline scrub by time using existing `seconds_at/index_at_seconds` with key-play ticks on the scrubber; speed/pause polish; instant replay with multiple camera angles; highlight bookmarks (user-added, saved in Preferences/profile-local data — decide format; if it touches saved data, add migration + `DATA_VERSION` bump per CLAUDE.md); highlight reel autoplay. Determinism: add a test proving `FcReconstructor.build` is byte-identical across runs and that replay windows map to the original event indices; document limits explicitly (no claim of exact reconstruction).

**M5 — Arena presentation (Phase 5).** In `court_scene.gd`: team-coloured crowd by section loyalty, idle variation and reactions to groan/oh cues (not just cheers), wave; richer lighting (spots, fog/glow tuned for gl_compatibility); court logo/team marks; LED boards with team/Full Court brand text (texture, rotating content, end-line boards); benches with seated characters; hoop nets; player-introduction camera sequence. Perf gate: run `tools/perf_benchmark.ps1 mode=replay3d` vs thresholds; crowd updates via MultiMesh without per-frame full rewrites.

**M6 — Audio + commentary foundation (Phase 6).** `FcAudio` additions: looping ambience bed (synth recipes), crowd intensity level driven by game state, ducking, PA announcement cue ids, basketball SFX hooks. New pure `FcCommentaryEvents` (typed events from the timeline with priority, cooldown, repetition prevention) feeding a swappable `FcCommentarySink` (caption text now; recorded voice/TTS/AI later). No network dependency. Existing `FcCommentary` becomes a phrase source. Accept: unit tests for prioritization/no-repeat; live audio test updated.

**M7 — Broadcast production (Phase 7).** Pure `FcProductionPlan` building segments from existing data: pregame (starting-lineup intro sequence with spotlight), halftime analysis (team card, leaders, run), postgame coverage, highlight package, milestones, championship presentation (when the game context is a title game). Rendered through the M1–M6 overlay/camera/audio systems in all three modes.

**M8 — Hardening.** Regression suite additions for spectator/replay, full perf soak/leak runs (`replay3d standard|camera|soak|leak`), screenshot matrix, 2D-fallback verification (`force_failure`), docs (see below), final CI check.

# Founder review additions (approved: M1–M8 structure stands; incorporate these without rewrites)

## Cross-cutting foundations (done at the start of M1, before refactoring FcReplayScreen)
**A. Shared state ownership.** Write a short design note first (`docs/plans/BROADCAST_PASS2_PLAN.md`): one `FcPlaybackState` (pure RefCounted: event index, play/pause, speed, instant-replay window, camera mode) owned by the screen shell and READ by every mode view; each mode (`FcBroadcastView`, `FcReplayView`, `FcAnalysisView`) owns only its own UI state (panel collapsed flags, selected filters, selected player). Mode switches never mutate playback state. Distinct experiences:
- **Broadcast** (immersion): full-screen 3D, director in AUTO, scoreboard + lower thirds + spotlights + captions only, feed/camera panel hidden, minimal transport that fades.
- **Replay** (review plays): timeline with key-play ticks, speed/step/loop, angle chooser, bookmarks, highlight navigation, contextual camera panel.
- **Analysis** (information/tactics): tactical overhead default, feed + box/team comparison + player lines, shot-location/run/lineup panels, free-roam manual camera, 2D flat available.

**B. Presentation event provenance.** New pure `FcPresentationEvent` record layered over (never mutating) event rows: `source` (SIM_RECORDED | DERIVED_FROM_RECORDED | RECONSTRUCTED | PRESENTATION), `t_tenths`/`seconds`, `confidence` (EXACT | DERIVED | APPROXIMATE), `importance` (0–100 from M4 model), `actions` (supported presentation actions: camera presets, graphics, audio cues, replay-eligible, bookmarkable). Rule enforced by tests: any graphic/commentary/stat text must trace to SIM_RECORDED or DERIVED_FROM_RECORDED; RECONSTRUCTED data (positions, shot clock, pass paths) is only ever shown with the "reconstructed" label and never in statistics or commentary facts.
**19.5% timing investigation (M2 prerequisite, documented in `docs/validation/B2_PASS2_RECONSTRUCTION_TIMING.md`):** from B1 report — 5,514/28,213 steps compressed, rebound 87.9%, dead 37.4%, loose 32.5%, hold 6.4%; shots/passes/FTs 0%. Impact on dependents: shot clock (must not be derived from compressed steps → confidence APPROXIMATE, hidden after rebounds/steals when unreliable), camera director (cut/whip rather than slow follow on compressed steps), character speed (cap at 22 ft/s, use reconstruction step length as dwell, max 3.7 s), replay accuracy claims (event order and score exact; between-event motion approximate), commentary (never mention speed/distance). Re-measure with `tools/reconstruct_spike.ps1` and record in the report.

**C. Broadcast identity kit.** One data file `data/ui/broadcast_identity.json` + `FcBroadcastStyle` (pure accessors) defining typography (reuse design tokens/fonts in `src/ui/` token layer — no new fonts), team colour/crest usage rules (via `src/ui/team/` resolvers), scoreboard layout metrics, lower-third and spotlight templates, transition set (cut, wipe, fade, whip) and animation timings (in/hold/out ms, reduce-motion variants). All overlays (M2), camera transitions (M3), production segments (M7) read it; the style-lint test continues to forbid raw colours/sizes. Visual acceptance: a "style sheet" screenshot of every graphic at 3 resolutions.

## Shared state ownership (written before the M1 refactor)
- `FcPlaybackState` (pure) owns: event index, playing, timer, speed, instant-replay window, camera mode, view id. `FcReplayScreen` exposes the old names (`speed`, `_index`, ...) as thin accessors over it, so existing tests and callers are unchanged.
- `FcPresentationMode` (pure) owns: which panels each mode shows, the default camera/view per mode, and what each HUD level (Full, Minimal, Hidden) hides. The screen only applies it (`set_mode`, `set_hud`, `apply_layout`).
- Mode UI state (folded panels) lives in the screen's `collapsed` dictionary; the chosen mode and HUD level are remembered in `FcPreferences` (`presentation_mode`, `hud_level`, additive, with defaults and validation; no world-save change).
- Rule: a mode switch never changes `FcPlaybackState` (live-tested, including during an instant replay).
